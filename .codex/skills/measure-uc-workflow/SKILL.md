# Measure UC Workflow

Read [FILE-DRIVEN-WORKFLOW.md](../../../docs/00-context/workflow/FILE-DRIVEN-WORKFLOW.md), [selection schema](references/selection-schema.md) and [phase ledger](references/phase-ledger-schema.md). The normal researcher interface accepts `$measure-uc-workflow close-phase <prompt_generation|source_generation>` and `$measure-uc-workflow finalize-workflow`. Finalize closes or skips Repair and finalizes the workflow atomically in the same excluded measurement turn. Each invocation authorizes its operation; never ask another approval or execute later source/audit/repair work.

1. Resolve exact existing UC/run, rollout, current measurement turn ID and prior completed work. Never choose newest/largest-token evidence. Build cumulative selection with one semantic phase/reason per work turn; preserve closed measurements and explicitly exclude close/report/export turns. Missing counters/endpoints stay null with reasons.
2. For prompt close, the invocation also approves the Draft: run `advance-experiment-gate/scripts/record_command.py --run-json <canonical.json> --action approve-prompt --prompt <configured-prompt.md> --turn-id <current-id>` (dry-run first). Preserve a run-local approved snapshot if the common path will be reused. This is not a separate researcher turn. Do not require activation.
3. Run `scripts/measure_uc_tokens.py close-phase --run-json <canonical.json> --selection <selection.json> --measurement-turn-id <current-id> --phase <prompt_generation|source_generation>`, or `finalize-workflow` with the same identity arguments and no phase. The helper automatically records the corresponding internal command receipt. Prompt close also creates missing `run-activation.json` from the pinned configuration/approved prompt (docs/02-construction/coding-prompts/<UC-ID>-business-coding-prompt.md) and this actual prompt-close turn, validates an existing receipt without overwriting it, and stores its canonical reference. No separate activation command/turn is needed. If a non-final receipt persistence failed, retry `record_command.py` for that step without recalculating an already closed measurement.
4. Finalize requires saved automatic final verification/hash/status after correction. It closes an open Repair bucket, or records a skipped Repair bucket from the persisted all-passing/no-repair decision, recomputes and validates every phase/workflow aggregate, prepares the internal Repair-close and Final receipts in order, then commits canonical telemetry and both transitions together. If any prerequisite, Repair close, aggregate validation or transition fails, it must not mark the workflow finalized. Finalization retries retain the committed Repair state. Blocked/stopped/declined terminal outcomes may finalize without being called successful. No separate Repair close, final-audit, repair confirmation or Final Metrics confirmation is required.
5. Print the five token fields, execution seconds and turn/tool counts; persist canonical metrics, ledger and derived reports. End with the next command. Never inspect or export Excel here.

## Evidence rules

- Use cumulative `total_token_usage` deltas, duplicate suppression and reset fallback to `last_token_usage`. Input/output/total must be available and consistent. Missing cached/reasoning counters are `null` with reasons.
- Report only input, cached input, output, reasoning output and total. Cached is a subset of input; reasoning is a subset of output. Do not export fresh-input, cache-write, monetary costs or a core-three-phase sum.
- One turn is indivisible. The AI assigns its primary token phase and evidence-based reason; code sums observed counters by that label. When a turn contains captured Prompt, Source or Repair execution, its token label must match that core phase, including an unfinished captured interval. In particular, repair's integrated audit cannot be relabeled as standalone `audit`. Configuration/approval-only turns without core execution stay auxiliary even inside an open generation bucket. Mixed turns receive one label, never an invented token split. Boundaries still close measured generation results and enforce work gates; they do not force auxiliary-only tokens into generation. The script enforces captured phase consistency, not semantic intent when execution evidence is absent.
- Read the printed token-label breakdown and per-turn reasons before reporting the result. Observations use metrics schema 3 with timing protocol `generation_execution_with_repair_audit_v2`.
- `workflow_turn_count` counts selected researcher-initiated turns; `tool_call_count` counts observable tool invocation records (deduplicate call IDs). Nested calls inside a shell/orchestrator are not automatically separately observable. Telemetry update counts remain diagnostics, never model/API call counts. Model-call count is `null` unless a separately validated exact request schema is implemented.
- Capture live execution intervals with the shared helper at the specified START/END boundaries. Token `phase` must match any captured core `timing_phase`; whole-turn token scope is still broader than its timed interval. Phase seconds include only core execution intervals; workflow seconds = Prompt + first-pass Source + all Repairs, including integrated repair audit and final evidence persistence. Standalone audit remains auxiliary. Auxiliary-only turns have zero counted execution seconds with an exclusion reason, not fabricated zero elapsed time. Missing core endpoints or pending phases yield null with reasons, never partial totals. Do not move/recreate timestamps during classification or substitute UI Worked-for, tool duration or whole-chat elapsed time.
- The full-file session hash changes as the task continues; completed-turn prefix hashes preserve stable evidence across later measurements. Never rewrite a closed phase's selected turns or results.
- Audit owns BR evidence/results. Measure owns `metrics`. Preserve unrelated JSON keys, recorded run evidence and external reference projects.
- Excel is outside Measure. A later export failure never changes canonical metrics and is retried only through `export-experiment-excel`; never repeat or alter a Measure boundary for reporting.
