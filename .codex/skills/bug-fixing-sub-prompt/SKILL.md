# Bug-fixing Sub-prompt

Read the pinned DBML and [database policy](../../../docs/00-context/engineering/DATABASE-SCHEMA.md). Before repair START run `<python-executable> .codex/scripts/validate_experiment_configuration.py <pinned-configuration.json>` to recheck every frozen API path/identity/SHA-256, then run `<python-executable> .codex/skills/gen-coding-prompt/scripts/database_baseline.py --configuration <pinned-configuration.json>`. Failure blocks correction without replacing inputs. Repair may fix entities, queries and services to use existing structure and perform authorized DML. It cannot change DBML, schema, indexes, constraints, grants or migrations, reset a volume or enable synchronization. Child audit rechecks the same pins after verification while the repair timer remains open.

Invoking `$bug-fixing-sub-prompt` authorizes this repair operation. Read [sub-prompt.template.md](../../../templates/construction/sub-prompt.template.md) as this skill's private prompt contract. Consume the validated canonical run, accepted audit results and defect inventory as handoff artifacts; do not read producer-skill instructions merely because their artifacts are inputs. Resolve the exact UC/run with source telemetry closed, a saved initial BR/Flow/defect audit, and an evidenced open defect. Require conclusive accepted BR/Flow verdicts, except when the complete frozen inventory is `execution_blocked` by a recorded generated-source defect. Run `advance-experiment-gate/scripts/record_command.py --run-json <canonical.json> --action repair --turn-id <actual-id>` (dry-run first), then begin correction in this same work turn without another confirmation. Retain an existing recorded authorization if already recorded; never reopen terminal runs.

Saving either researcher or LLM follow-up results alone does not authorize repair. Acknowledge saved results and wait for this subsequent command. Normal `not_evaluable` BRs or flows block new repair authorization; `execution_blocked` permits correction of its evidenced blocking defect without a researcher verdict. Accept attributed normal researcher verdicts without fabricating or requiring a second LLM proof. Activation is optional; concrete source/schema/runtime prerequisites remain.

1. Select one evidenced defect from the canonical defect inventory or accepted BR/Flow follow-up results and retain its fingerprint. A technical defect may be selected even when no BR/Flow is incorrect; an execution blocker is selected from its recorded blocking defect IDs. Do not repair speculation or add a feature.
2. Create one numbered repair artifact with allowed files, affected BR IDs and permitted non-test checks under `docs/02-construction/implementation/<UC-ID>/runs/<RUN-ID>/repairs/`.
3. After planning, required resolution and authorization, capture `repair` START immediately before executing the correction. Pass the unique canonical `--repair-id` on both endpoints. Apply the smallest correction and keep this interval open through the integrated verification in step 4. Record model and exact turn/segment IDs per repair. End before any blocker resolution, researcher wait or response; resume correction or its unfinished integrated verification with a fresh segment for the same repair ID. Never finalize tokens in this turn.
4. After every correction, invoke the audit operation only as an explicit subordinate verifier in the same repair work turn to reassess affected BRs/flows and check integration using permitted typecheck/lint/build and bounded Docker runtime observation. Before the repair phase ends, assess every frozen BR and flow on the final source, persist final results and freeze `business_rules.source_revision`. Use fresh final-stage flow evidence under the configured rubric; preserve immutable initial results. Complete this work before returning. Capture repair END only after this integrated verification and final evidence/hash/status persistence. Its elapsed time is part of Repair; do not open a second overlapping audit/runtime interval or count it twice. The entire work turn retains token label `repair`, including the subordinate audit, not the auxiliary `audit` label.
5. Report successful repair only when the correction is verified. Persist unresolved defects, unknown behavior and runtime blockers honestly; use `blocked`, `stopped` or `repair_declined` when appropriate, never fabricate `met` or `correct`. Persist terminal `run_status` when no further authorized correction remains. If another evidenced defect remains and the run is nonterminal, stop after reporting the validated repair artifact; a later explicit invocation selects one new defect fingerprint and creates its own repair record. Do not start another top-level operation automatically.
6. Stop for the researcher if the correction needs a requirement/API/ownership/destructive-data decision, if the pinned database cannot support the requirement, or after the same defect fingerprint remains for three attempts. A schema blocker never authorizes an in-run schema change. Follow the database policy: capture actual END, preserve partial evidence and require a new configuration/run after researcher migration setup. For Docker rebuilds use `--no-deps backend frontend` so the setup migration service cannot run.

Do not create or run tests.
