# Run Third-party Final-source Security Scan

Read `AGENTS.md`, `PROJECT_CONTEXT.md`, `docs/00-context/security/SECURITY-TOOL-EVALUATION.md`, the Approved criteria catalog, product-level evaluation policy and input, `security-tools/compose.security-scan.yaml` and `references/result-contract.md`.

1. Require the complete generation/audit/repair workflow for the current research-product output to be terminal. Freeze the current `finalsource/` tree hash; reject active or ambiguous generation state. The evaluator does not select or interpret a UC.
2. Operate as an **SR-blind evaluator**. Do not load or receive SR IDs, security resources, Prompt E/coding prompts, generation audit/repair records or experiment-run reports. Read only the Approved evaluator input/policy, checksum-bound tool contracts/rules/version lock, frozen `finalsource/` and evaluator-owned output. Treat `contributing_uc_range` as provenance only.
3. Require an Approved catalog under `security-tools/criteria/`, an Approved catalog-bound policy under `security-tools/evaluation-policies/` and an Approved input instantiated from `templates/security-evaluation/final-source-security-evaluation-input.template.json`. If no input path is supplied or no Approved input exists under `docs/03-audit/security-tools/finalsource/inputs/`, stop before Docker or scanner execution and direct the researcher to run `$prepare-security-evaluation-input`. Do not create or self-approve the missing input inside this skill. Validate A01/A02-only scope, official source records, criterion uniqueness, rule origin/maturity, evidence fields, limitations, research-product identity, researcher decisions, pinned central version lock, catalog/rule checksums, exact enabled-criterion equality and explicit coverage limitations. These inputs are evaluator-only and must not be linked from a UC security resource or coding prompt.
4. Run `.codex/skills/run-third-party-security-scan/scripts/run_third_party_security_scan.py --evaluation-input <approved-input.json>` from the repository root. It builds the isolated final runtime, waits for health, records researcher URLs, verifies the approved current-source hash, runs Semgrep/ZAP read-only, and writes only under `docs/03-audit/security-tools/finalsource/<evaluation-id>/`.
5. Semgrep/ZAP must not modify source/configuration/prompt/generation audit. Never invoke `$bug-fixing-sub-prompt` or another generation component from a finding. Any later remediation requires a distinct researcher-authorized run.
6. Normalize configured A01/A02 rule results. New scanner alerts are `potential_finding` pending researcher triage. Do not automatically emit `confirmed_finding`, SR `met`, SR `unmet`, or a claim that A01/A02 is absent.
7. Keep criterion definitions and sources canonical in the checksum-bound catalog and execution selection/coverage canonical in the policy. Use the Semgrep and ZAP input/output contracts under `templates/security-evaluation/`; their raw/native output remains ephemeral. Record the catalog reference, criterion ID for each configured finding, combined tool completion and observed target/context/probe coverage in the product-level schema-version-5 `evaluation-summary.json`; validate it with `scripts/validate_evaluation_summary.py`. When a coverage unit cannot be assessed, record `not_evaluable`. Preserve outside-policy alerts as `unscored_observation` when available.
8. Leave the healthy Compose stack running for researcher inspection and return URLs, the safe non-volume down command, source-unchanged result, manifest, normalized findings and coverage summary. Redact credentials, tokens, cookies and sensitive request/response bodies.

Only the researcher may perform a separate post-hoc comparison between already-finalized SR/generation evidence and this already-finalized evaluator result. That analysis is outside this skill and must not mutate either side or reopen the completed run.

Do not create functional tests/test cases. Report only what the frozen policy and observed coverage support.
